# 游戏资源自动更新：资源范围与交付设计

本文是独立实现方案。资源族、输入约束和验收方法可以用于实际项目整合；本仓当前通过的自动测试使用原创合成资源。清单里列出某项，不表示其真实游戏版本提取器已经完成。

## 1. 从页面消费资源出发

资源不按页面各存一份。页面只保存 ID、筛选条件和对共享资源库的引用。

| 页面功能 | 需要共享的资源 | 不属于公共游戏资源的内容 |
| --- | --- | --- |
| 世界基础信息、标记与预览 | 地图颜色、方块/墙壁语义、实体图标、名称 | 用户世界、解析结果、缩略图、后台配置 |
| 像素画与写入 | 材料列表、油漆运算、候选调色板、RGB 最近色索引、TXCI | 用户图片、自定义映射、写入任务 |
| 玩家与背包编辑 | 物品、前缀、Buff、装备槽、人物纹理、造型选择与帧规则 | 用户 PLR、人物颜色选择、编辑状态 |
| 宝箱 | 物品名称、堆叠上限、图标、前缀适用范围 | 世界里的具体宝箱与物品数量 |
| 方块替换与材料选择 | 方块/墙壁名称、样式、帧布局、形状、放置物品关联 | 用户替换规则和预设 |
| 图鉴 | NPC/net ID、图鉴持久 ID、中文名、类型、图标 | 当前世界解锁进度 |
| 世界生成 | 选项 schema、默认值、范围、帮助、步骤、可用实体选项 | 用户种子、生成任务、生成后的世界 |
| 通用帮助与设置 | 资源版本、功能能力、应用说明 | 登录、权限、广告配置、业务接口 |

保存解析器 WASM、业务 JS 和游戏资源是不同问题。可执行代码更新需要对应应用发布策略；用户存档永远不会进入公共资源包。

## 2. 两类原始输入，多个派生输出

服务端包可提供程序集中的 ID 常量、本地化，以及经可信版本适配器求得的运行时数据。它不能凭空提供客户端独有的完整纹理。

客户端 Content 提供 XNB 等纹理输入。解码 PNG 也可以作为输入，但必须证明来源版本、原文件与解码器版本，不能凭目录名字当作来源证明。

每次任务绑定：

- 服务端归档及选定程序集 SHA-256
- 客户端归档、文件清单与纹理树 SHA-256
- 提取器、解码器和规则适配器版本及工具文件散列
- 元数据与派生算法的输入散列
- 输出对象、资源目录、覆盖报告及最终版本散列

不同游戏版本不能因文件名相同而共用元数据。相同输出字节可以内容寻址复用；语义来源仍记录在各自版本清单中。

## 3. 14 个逻辑资源族

| 资源族 | 需要验证的主要内容 |
| --- | --- |
| ids | 命名空间、ID 常量、别名、计数与排除项；Count 等元常量不当实体 |
| locales | 中英键、命名空间、回退、未解析引用 |
| items | 标识、名称、字段 schema 与默认属性、说明模板/解析上下文、研究、分类、装备与放置关联、原图与缩略图 |
| tiles | 名称、地图多选项、属性、布局、样式/alternate/random、帧、形状、放置关联、原图、说明来源 |
| walls | 名称、地图选项、属性、放置关联、原图、说明来源 |
| paints | ID、名称、输入颜色、混色规则、特殊涂层、支持状态 |
| npcs | 原始 ID、net ID、持久 ID、图鉴成员、类别、名称、说明来源、图标裁切 |
| buffs | ID、名称/说明、负面状态、物品关联及需要的图标 |
| prefixes | ID、名称、倍率、可用对象与例外规则 |
| player | 发型、身体、各装备/饰品/翅膀纹理、索引映射、造型预览、帧修正、染料注册、渲染能力与未支持动作 |
| worldgen | 选项 schema、默认值、枚举、范围、帮助、生成步骤、种子能力、宝箱物品集合与来源字段 |
| markers | 选择器数据、类别、裁切矩形、缩略图及应用策略版本 |
| map | 完整方块/墙壁选项、液体与背景、油漆/光照/涂层及特殊规则 |
| pixel | 候选白名单与排除理由、顺序、分组、SRGB/TXCI、编解码版本、调色板绑定与可选图库 |

现有协议将这些内容分为 110 个可检查子项。一个物理文件可以合并多个子项，但不能用“文件存在”替代逐 ID、字段、关联和来源的完整性检查。

### 不能省略的语义区别

1. 小型物品目录不等于完整属性与说明。复杂属性必须给出字段结构、可导出值与不支持类型；动态说明还要记录解析上下文，不能只复制语言键。
2. 原始纹理、图集裁图、预览缩略图和别名必须区分。缩略图覆盖全部 ID，并不证明全部原图已经提取。
3. 人物走路预览不能代表跳跃、骑乘、使用物品等所有动作。清单应明确支持动作和渲染规则的适用版本。
4. NPC ID、图鉴持久 ID 与数据库记录 ID 不可混用。中文名称字段统一转换，回退路径也要测试。
5. 地图色不是图片平均色。油漆、光照和特殊分支会影响结果；有限稳定材料子集不能替代完整地图调色板。
6. RGB 索引必须绑定候选顺序与调色板散列，否则文件能解码也可能选错材料。
7. 后台自定义分类、帮助文案和世界生成扩展选项可能来自应用基础设施，不能都归因于游戏程序集。

## 4. 发布布局与体积控制

建议保持四层：

- 小型版本指针：只指向已审核版本，包含前一版本标识
- 客户端目录：资源族索引、共享字符串和按需详情对象的引用
- 不可变对象：内容散列命名，压缩元数据与无损图片跨页面、跨版本去重
- 审计证据：输入绑定、覆盖策略、逐项证据与差异报告，独立对象保存，不要求小程序启动时全部下载

小程序主包只保留必要启动逻辑、极小占位资源和加载器。物品详情、人物大图集、RGB 索引在进入相应功能时加载，缓存有容量限制。离线只保证已缓存且校验通过的对象，不宣称首次离线也能下载新资源。

客户端更新先验证目录和公共字典，成功后再切换快照；失败继续使用原快照。SHA-256 检查保证对象符合指针，不替代发布者身份认证；生产版本指针必须通过可信 HTTPS/发布来源获取。

## 5. 上传到发布的边界

1. 上传：归档流式保存到私有任务目录，限制总体积、文件数、展开比例与路径；不执行归档里的脚本
2. 预检：核对双输入、真实散列、已支持版本和已注册工具；缺失内容明确列出
3. 提取：固定工具参数、只读输入、无网络及资源限制；不能由上传内容指定命令
4. 校验：逐 ID、字段、关联、图片、说明与来源检查；未知或缺失必需项阻止完整发布
5. 审核：展示新增、变化、删除、体积、覆盖和风险；确认绑定本次输入、输出与发布基线
6. 发布：重新验证暂存对象及证据，再生成 Git 提交；远端成功确认后更新任务状态
7. 加载：按需读取不可变对象，失败保留旧版本，重复点击或恢复不重复写入

本仓使用真实的本地 bare Git 来模拟第 6 步，不会写现有 CDN。生产整合还需要既有后台身份验证、角色权限、作业队列、配额、可信发布配置，以及操作者确认后的主动回滚界面。

## 6. 真实版本最终验收清单

- 使用真实且同版本的服务端和客户端输入，不借用合成 CI 结果
- 对照实际页面资源域，证明所需 ID/字段/图片/帧无缺失；每个例外有明确理由
- 随机与边界实体核对中文名、属性、动态说明和纹理；别名、空洞与有符号 ID 单独测试
- 对油漆特殊分支、浮点舍入、候选顺序和 RGB 索引做可重复的参考对照
- 页面加载旧/新版本、更新中断、损坏对象、离线缓存、清理缓存、重复确认均有测试
- 统计主包体积、首次页面流量、重复访问流量、缓存占用与解析峰值内存
- 审核差异后发布，验证客户端版本更新；未确认、覆盖不足和来源不符均不能发布

这些项目是验收目标，当前状态以实际测试报告为准。
