# 单次完整 Content 上传的有界纹理解码

一个 Content ZIP 对应一个原始输入任务。后端自动规划顺序执行的子批次；用户不必拆 ZIP，也不必预先转换 PNG。单批仍使用已固定哈希的第一方 TextureExtractor，通过原有 bubblewrap 隔离执行；不会运行上传的 EXE、DLL 或 XNB reader 类型。

## 固定边界

| 边界 | 上限 |
| --- | ---: |
| 每张纹理首层像素 | 16,000,000 |
| 每个转换进程首层像素 | 256,000,000 |
| 每个子批次文件 | 256 |
| 每任务子批次数 | 256 |
| 并发转换子进程 | 1 |
| 每转换进程地址空间 | 2 GiB |
| 每任务实际首层像素总和 | 1,024,000,000 |
| 每任务 XNB 声明展开字节总和 | 4 GiB |
| 每个纹理任务私有目录总字节 | 2 GiB |
| 整个原始输入处理截止时间 | 120 秒 |

1,024,000,000 像素是四个既有 256,000,000 像素处理窗口的**累计顺序工作额度**，并非新的单进程分配上限。它覆盖已观察到的 549,576,440 首层像素完整 Content 规模，仍显式拒绝更大的整包工作量。4 GiB 约束声明展开工作量；它不会被一次性展开到内存或磁盘。所有既有单图、单进程内存、文件大小及隔离限制保留。

120 秒由原始输入预检传入，包含归档校验、展开、批次准备、解码、PNG 验证及后续阶段。子进程仅得到剩余时间，不会每批重新获得 120 秒。Python 阶段在每个文件/目录条目，以及复制、文件哈希和 PNG 读取的每个至多 1 MiB 块之间检查同一个截止时间与取消信号；单图 PNG 解码前后也检查。子进程由 watchdog 终止。取消清理仍须完成，不因已过截止时间而跳过。

## 不解码 XNB 的批次规划

规划器只读取 XNB 的 10/14 字节固定头，验证平台、版本、flags、实际文件长度和声明展开长度。每文件的保守像素风险为 min(16,000,000, 2 × 声明展开字节)，其中 DXT1 每像素至少半字节，其他支持格式不会比它更密集。接近 256 文件或 256,000,000 风险像素时，自动结束当前批次。

这种预先拆分不依赖失败后的猜测重试，不会把损坏的纹理反复送入转换器。风险值只用于单批规划；实际全任务像素额度来自逐 PNG 重新读取、解码和检查的尺寸，避免把 RGBA 当作 DXT1 高估而误拒绝正常整包。

## 磁盘、取消和失败

任务保留一份只读来源快照及一份转换器快照。不可变快照占用从同一个 2 GiB / 50,000 路径额度中预先扣除。创建子批次副本前先核算所需字节。每批通过验证后，PNG 原子移动至统一 output 并设为只读，随即删除子批次目录；不会留下数十份输入或工具副本。

多批次任务中，每个 child 使用不同的私有目录；其 sandbox 仅挂载该 child 的输入、工具、临时目录与输出，不能访问已合并的父级 output。程序也拒绝将父级 output 或其上级路径挂入 child 的计划。已验证 PNG 的实际文件长度、相对路径和 SHA-256 进入不可变额度记录；长度来自文件系统清单及独立 PNG 校验，不能采用回执自报的数字。文件与共享父目录均计入路径额度。

watchdog 仍逐项扫描全部可变 work，包含活动 child 的输入、工具、临时文件和输出，并将已验证父级输出记录的字节/路径计入同一个总额度。它仅避免每 25 ms 重复遍历 child 无法访问的累计 PNG，不跳过可变区域的检查。重命名合并前还计入暂时并存的新父目录；最终回执的临时文件也须先满足总额度。单 child 任务继续扫描全部 output 与 work。

所有 child 退出后，必须重新完整扫描 output/work，重新哈希全部 PNG，并对比累计记录的文件长度、哈希及目录集合。来源和工具的最终校验也保留。此优化没有提高 120 秒、2 GiB、50,000 路径、256,000,000 像素或任何子进程限制。

原始上传 ZIP 与来源预检记录在纹理私有目录之外，保留用于来源审计，仍受各自原有上传/展开额度约束。它们不会因纹理解码取消而删除。

取消会杀死当前子进程组。任何失败、超时或取消都会删除纹理任务的私有目录，清除已合并的部分 PNG 和回执。当前不支持部分批次恢复优化；重试重新验证来源并从干净任务开始，绝不复用未验证的中间回执。已完成的同一路径不会再次执行或覆盖。

## 回执和发布边界

最终输出继续位于 <role>-texture-job/output，保留全部原始相对路径。回执必须一一覆盖输入 XNB，每个 PNG 的文件 SHA-256、尺寸及解码 RGBA SHA-256 都重新验证；合并后再次检查 PNG 文件哈希，原始来源和工具哈希也再次验证。

新转换器记录 mipLevels 和 exportedMip=0。所有声明 mip 数据均由转换器校验，但仅导出 mip 0；不能据此宣称导出了全部 mip。旧转换器省略这两个字段时保持未知，不推定只有一层。

成功解码纹理不等于完整语义抽取或发布许可。extractionComplete 和 publishable 继续为 false。任何部分或失败的任务都不能成为发布候选。

## 验证范围

tests/test_texture_batches.py 使用合成固定头和已知 PNG 的模拟转换器验证规划、预算、取消、清理、完整合并和失败关闭，不运行游戏输入。真实完整 Content 单次上传及已编译转换器的验证须另行在获准的隔离环境运行；这些合成测试不能替代真实整包验收。
