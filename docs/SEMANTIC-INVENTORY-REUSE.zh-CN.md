# 复用本地 ZIP 哈希清单，保留语义阶段最终校验

原始输入预检的 extract_zip 已在逐文件写入时计算实际 SHA-256、长度和安全相对路径。内置 RawEvidenceProducer 可以接收这份刚计算出的清单，省去语义阶段第一次重复遍历；不是上传字段，也不读取上传文档里的清单声明。

## 可信调用边界

- 预检保留一份独立于任务记录的文件清单副本，只使用当前 extract_zip 调用生成的数据
- 只有 type(producer) 恰为内置 RawEvidenceProducer 时，预检才传 expected_inventories
- 注入的生产器或子类保留原有调用参数，不能自动进入此优化
- 直接调用内置生产器但未提供 expected_inventories 时，仍执行原有初始与最终两次 tree_inventory

## 使用前验证

所有来源角色的元数据必须在任何来源文件内容读取前完成验证。角色必须与来源根目录完全对应；每行仅含 path、bytes、sha256，并验证安全相对路径、整数长度、小写 SHA-256、重复/大小写冲突、文件与目录冲突，以及原有单文件 128 MiB、合计 2 GiB、50,000 文件/派生路径上限。清单被复制并按相对路径排序。

随后验证来源根目录及其父路径不经过符号链接。实际要读取的 TerrariaServer.exe 通过 package_file 检查每一级路径，避免省去初始遍历后漏掉链接父目录。静态解析前仍计算实际可执行文件哈希，必须与已验证清单一致；文件仅作数据读取，不执行。

## 最终校验不可省略

生成最终 version-adapter-manifest.json 之前，仍必须对每个完整来源目录运行完整 tree_inventory，并逐项比较路径、文件长度和 SHA-256。增加、删除、改写文件，伪造长度/哈希，或插入符号链接都会拒绝该回执。截止时间和取消回调继续作用于元数据验证、文件读取及最终全目录哈希。

失败时不会生成成功的语义 manifest；已经生成的部分文件仅留在私有任务目录，沿用现有失败/取消清理策略。extractionComplete 和 publishable 始终为 false，此优化不会改变发布门禁、放宽时间或资源限制。

## 本地验证范围

tests/test_semantic_inventory_reuse.py 使用原创惰性文本/字节与模拟静态检查器，验证少一次目录遍历、顺序规范化、严格输入校验、路径链接防护、最终篡改检测、取消，以及预检对内置与注入生产器的不同调用。合成性能比较不能替代真实双 ZIP 整体 120 秒验收。
