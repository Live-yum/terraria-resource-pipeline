# 静态服务端证据中的新建 Item 基线

`extract_server_semantics` 现在把独立的 fresh Item 分析作为 `freshItemBaseline` 附在私有服务端证据上。现有 `RawEvidenceProducer` 通过默认的 `inspect_server` 路径自然保存此字段，无需改变生产器或发布门禁。

每个程序集只有一份明确的新实例顺序：零初始化 → 真正的无参数构造器 → `ResetStats(0)`。证据带有输入 SHA-256、固定参数 `[0]`、方法与字段来源。其支持的元数据、初始化器快照条件、UNKNOWN 与诊断前缀规则见 [独立基线语义](FRESH-ITEM-BASELINE.zh-CN.md)。独立分析器自身仍然不知道生产器；接入点仅位于服务端证据组合层。

这份证据不按物品 ID 复制，不会用作已有 `SetDefaultsN` 阶段的初值，也不会把基线值作为所有物品的默认覆盖。阶段记录继续声明 `initialInstanceFields=unknown`。`finalItemDefaults=false`、服务端 `complete=false` / `publishable=false` 和各家族缺失项全部保留；生产器的物品 `defaults` 仍属于缺失规则。

## 合并预算

`itemAnalysisBudget` 明确记录两次分析的共享限制与收费。不会给两次分析各发一份完整的原始总预算：

- 总步骤：先分析阶段，再从原始 `total_steps` 扣掉阶段实际报告的步骤；基线仅获得剩余额度。沿用底层计数惯例，超限检查本身可产生一条被拒绝步骤，不能把它当作已证明执行
- 累计证据：预留 2048 字节给接入诊断和预算摘要，阶段可用额度先减去此预留；随后从余额扣掉阶段的累计构建收费，再交给基线。覆盖、丢弃或诊断替换不退费。接入信封与合并 JSON 都在返回前独立检查大小
- 总解码指令、总方法 IL 字节：由于既有分析结果不导出每次失败解码的完整用量，预先给基线保留四分之一容量，阶段使用其余容量。这是明确的容量划分，不是虚构的实际使用统计；剩余预留不会借回阶段
- 解码前收费：方法字节在读取方法体前占用累计容量；每条指令在读取 opcode/operand 前占用指令容量。未知 opcode、无效分支、后续语义拒绝等失败不退回已尝试工作，缓存拒绝结果也不会再次解码；四分之一预留因此约束实际尝试工作
- 墙钟：阶段和基线共用同一个截止时间；基线仅得到剩余秒数。外部取消与共享截止时间异常向调用方传播，不会伪装成正常的可跳过结果
- 单方法、栈、局部变量、字段/索引容量和调用深度继续使用各分析程序自身的原有上限

如果剩余步骤为零、没有可预留的解码容量，或剩余证据不足以支持底层 16 KiB 诊断信封，则基线为 `NOT_ANALYZED`，并给出明确 `reason`，没有字段终态。分析中才用完额度时保留底层的具体停止状态及诊断前缀，仍无终态字段。共享证据总额度必须至少为 18 KiB，以同时容纳既有阶段 API 的最小诊断额度和接入信封；更小的配置明确拒绝。

服务端完整结果继续受原来的 64 MiB `SemanticLimits.output_bytes` 检查，不扩大上限。畸形 PE/CLI 读取错误不会被降级成基线跳过。合法但不支持的 Item 形状仅产生带来源绑定的未证明结果。

## 摘要与验证

`scripts/ci_server_semantics.py` 的基线摘要使用封闭白名单：状态、数量、源 SHA-256、整份私有基线的规范 JSON SHA-256、固定重置参数与未完成标志。它不复制基线字段名、值、记录、诊断前缀、静态赋值或方法列表。完整证据和真实输入只保存在私有验收目录。

`tests/test_server_baseline_bridge.py` 仅使用原创合成 PE/CLI，验证真实检查器入口、默认生产器和 HTTP 上传路径中的证据传递、来源绑定、不支持的类型、预算扣减与跳过、取消/截止时间、原始输出大小限制、摘要不含字段数据，以及缺失 defaults 和发布阻塞不会被升级。测试不加载或运行游戏 EXE/DLL，也不调用 CLR。
