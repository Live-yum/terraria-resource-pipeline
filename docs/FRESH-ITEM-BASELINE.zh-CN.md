# 新建实例的 primitive 基线证据

`resource_pipeline.item_baseline.extract_fresh_item_baseline` 是独立、尚未接入生产器的静态分析 API。它仅读取 PE/CLI 元数据和 IL 字节，不加载或执行游戏程序集，不调用 CLR。它描述以下明确顺序：

0. 先检查 Item 类型初始化器的效果；没有初始化器与初始化器无法闭合是不同状态
1. 一个全新 Item 实例的零初始化存储
2. 该程序集真正的无参数实例构造器，包括字段初始化表达式
3. 该程序集真正的 `ResetStats(reset_type)`，参数默认是零

该证据不适用于已使用的实例，不接受调用者提供的字段初值，也不证明带参数构造器、`SetDefaults` 的分派、变体、food 路径或后处理。已有阶段分析 API 保持 `initialInstanceFields=unknown`，不会获得本 API 的零初始化假设。

## 输出与证明范围

输出始终为 `executedInput=false`、`complete=false`、`finalItemDefaults=false`。`baselineComplete` 只表示本次新建实例、构造器与重置的 primitive 字段在声明假设下全部已知，绝不表示最终物品属性完整。

每个 primitive 字段按 token 输出 `PROVEN` 或 `UNKNOWN`；未知字段不带 `value`。每个已知字段的证据区分 `fresh-zero`、`constructor` 和 `reset` 来源，保留字段签名或实际写指令、方法 hash/offset、已观察静态依赖等证据。较晚的未知写入会移除较早的已知值，不会回退到构造器值或零。

非 primitive 字段在 `excludedFields` 中明确排除。引用字段可以在内部跟踪 null；精确类型匹配的值类型零写入只跟踪 `opaque-zero`。这些状态不提供对象内容、nullable 值或结构体成员语义。

任何未支持的实例副作用、调用或控制流都会清空终态 `fields`。已观察的写入最多保留为 `prefixFields` 诊断，不能据此声称重置后的值。

## 新增的受限语义

- Item 必须直接继承来自外部 core-library AssemblyRef 的 `System.Object`，并检查名称、公钥 token、scope 和 culture；不接受仅同名的本地或外部类型。这是引用身份/元数据检查，不是程序集签名认证
- Item 必须是非泛型、非 interface、自动布局类型，无相关 ClassLayout/FieldLayout 记录；不接受继承实例存储或显式布局别名
- 仅精确裸 primitive 数值和 bool 签名可以获得零初值。native int、指针、byref、修饰签名、数组和未支持的泛型签名均不获得猜测值
- 无参数构造器必须唯一，ResetStats 的实例签名必须精确匹配。真正的 `System.Object::.ctor` MemberRef 仅按已验证的基类引用、名称和无参数签名识别，且必须在实例构造器路径中调用一次
- Item 自身的数值辅助方法必须是已验证的 static、无调用、无字段/对象访问的纯整数方法；方法名称不决定行为。其他声明类型的 helper 可能触发其初始化器，本基线不沿用阶段分析对这些初始化效果的较弱假设，因此暂不接纳
- `ldflda` 仅允许指向当前实例自身的非 primitive 值类型字段，必须在紧邻的下一条指令中由精确匹配的 `initobj` 消费。禁止复制、局部保存、传参、跳转携带、foreign receiver 或任意指针/别名操作
- null 引用 setter 必须具备精确类型签名，并且整个实际方法体恰好是加载 receiver、加载参数、写入同类型实例字段、返回。任何额外调用或副作用都拒绝；其他对象方法不因此被允许
- readonly 字段只允许在所分析的实例构造器阶段赋值，不能由 ResetStats 或 setter 改写

## 静态初始值与未知效果

`ldsfld` 不会按字段名替换成手写常量。数值必须来自所属类型真实 `.cctor` 的完整、正常返回、封闭标量数据流。静态依赖按实际 field token 解析，并拒绝循环、foreign 静态写入及未支持的调用和对象效果。未赋值的字段不会被猜测成零。

证据声明静态快照假设：已证明封闭的标量初始化器已经正常完成，此后没有对其 mutable statics 的写入。它不是运行时任意时刻的全局静态状态证明。

如果初始化器先写入常量，随后遇到未知 factory、虚调用、对象/数组操作或其他未关闭效果，整个初始化器的静态值都不能成为已知快照。此前的常量只保留在 `staticInitializers[].prefixFields`，实例读取得到未知值。依赖初始化器未闭合时，调用方也不能把前缀常量升级为已知快照；该规则同样适用于缓存命中与传递依赖。任何未闭合初始化效果都令后续所有静态读取未知（包括 initonly 字段）；若不确定效果在实例构造开始后才被发现，则整个实例终态证明拒绝，仅保留诊断前缀；这也覆盖先前静态分支跳过某次赋值、没有写入来源可追溯的情况。

局部 `.cctor` 正常返回与可使用的全局快照是分开的：每条初始化器证据提供 `snapshotUsable` 和 `snapshotScope`。其他初始化效果未闭合时，即使本地标量赋值可与源码对应，也只能保留诊断，不能作为已验证快照。仅数值未知但效果闭合的初始化器不因此污染独立常量。即使参考源码显示常量，这一规则也不放宽。

## 预算与验证

沿用原有默认步数、时间、方法数、IL 字节/指令数、栈、局部变量、调用深度、字段数、元数据扫描、名称和累计证据上限。实例方法、标量初始化依赖与 null setter 的指令共用总步数；静态依赖深度也计入调用限制。所有新证据被累计收费，返回前执行完整 JSON 大小检查；取消和读取错误会传播。

测试只包含原创合成 PE/CLI 和独立数值，不包含游戏 IL、源码、资产或真实提取结果。覆盖零初始化、构造器/重置覆盖顺序、readonly 价格式辅助计算、引用/nullable 排除、类型身份和布局、字段地址逃逸、静态依赖循环、写常量后发生未知调用、错误元数据/IL、共享预算和取消。真实输入及逐字段源码交叉检查仅保存在私有验收目录。
