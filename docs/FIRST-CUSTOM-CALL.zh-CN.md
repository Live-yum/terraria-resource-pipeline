# 首个 CreateCustomSet 调用的静态状态桥接

`factory.firstCustomCall` 将独立构造器和空 pairs 方法证书，连接到 `ItemID.Sets` 初始化器的第一段精确 IL。仅解释字节，不加载 CLR 或运行游戏。

证明边界为单线程、无外部干扰的 CLI 执行，且相关操作正常返回：

- 第一条 Count 静态读取的值直接传入新 Factory 构造器。这个值是符号值，不能替换成 Count 初始化器曾经写入的字面量，因为该初始化器仍有未闭合调用。
- 新 Factory 仅被保存到精确绑定的 Factory 字段，随后立即读回。它不是“从未逸出”：静态字段发布被显式记录；并发或外部改写不在证明内。
- 到目标调用之前不允许其他调用、分支、未知指令、引用别名、实例字段变更。Factory 的隐式类型初始化器会被拒绝。
- 默认值可以是 int32 字面量，或一个无方法、无引用、无重叠布局的整数结构体。结构体通过精确绑定的第一个局部变量 initobj，然后接受有界整数常量字段赋值，并按值加载。泛型 MethodSpec、结构体、局部和每个字段都必须匹配。
- 空 object[] 参数和已证明的 CreateCustomSet 空路径共同推出：返回全新数组，长度等于捕获的 Count 读取，每个元素为已证明的默认值副本。不会推出调用必定成功、数值长度或运行时快照。

残余统计只移除这一个 caller token + IL offset + target token 对应的调用，不移除同 MethodSpec 的其他出现，不移除构造器或 Count 初始化器的其他调用。整个初始化器、完整提取和发布门禁仍然关闭。

原创测试覆盖正常整数/结构体默认值、重复目标调用仅扣除一次、Count 未知调用仍保持符号大小、前缀调用/写入/地址逸出、错误局部/字段/布局、分支、异常区、预算和取消。
