# SetFactory：共享新实例状态的有界前缀证明

`set_factory_lifecycle.prove_factory_lifecycle_prefix` 将独立构造器和首个空参数 custom 调用的证据组合为一个连续、无未知调用穿越的初始化器前缀。它只解析 PE/CLI 数据，不启动 CLR、不执行输入。此证明不是完整初始化器或运行时快照。

## 状态与转移

- 起点继承精确首调用证书：唯一新 Factory、构造时捕获的 Count 读取、独立空队列和新锁。Count 是符号值，不将之前的字面量赋值假设为每次读取的实时值。
- Factory 只发布到已绑定的 Sets.Factory 字段。在单线程、无外部干扰的前提下，只有已证明方法能跨越这个发布点；“调用未传入 Factory”本身不构成安全理由。
- 受支持的 bool/int getter 必须完整通过原有 IL、签名、异常处理和核心库身份检查；其 size、queue、lock 字段还必须与构造证书精确相同。不能仅凭方法名或队列名称判定。
- 前缀内队列一直为空：已接受的 Create 方法没有 Enqueue，没有接收未知别名，没有回收调用。每次 getter 都走新数组分配路径，保持队列为空；不同调用位置构成不同分配身份。
- 数组状态记录元素类型、符号长度、默认值和按顺序的覆盖写入。参数 int[] 支持零初始化、精确 RVA 初始化和有界直接写入；重复索引遵循最后写入。正常返回条件蕴含结果索引在界内，但不保证调用一定正常返回。
- 精确的核心 List<int> `.ctor` / `Add` 实例签名、TypeSpec、元素类型和库身份允许作为受信 intrinsic。该约定包含类型初始化，允许修改新 List、其私有存储及核心库自身的初始化状态（例如静态空数组）；不影响 Factory、池或游戏状态，不调用用户转换、比较器或回调。它不是对外部程序集实现的密码学认证。其他泛型类型或同名方法不能获得这个效果摘要。
- 结果只允许存储到当前执行的 Sets 所有者中签名完全匹配的静态字段；不跨越其他类型初始化、不允许 byref、Factory 替换、未知字段写入或未知调用。

每个完整片段以事务方式提交证据：若最后的字段存储或任一操作无法证明，该片段的所有调用都不被移除。已接受片段后遇到未知操作立即停止，不能继续用旧的队列/数组事实证明更晚调用。完整 caller IL 已被前置证书检查为无分支和异常区，因此不能从后缀回跳到已证明前缀。

残余计数按 caller token、IL offset、target token 三元组移除已证明的发生位置。相同目标的更晚未证明调用仍保留。证据保留输入 SHA256、完整方法 IL/签名散列、字段所有权以及 List 成员/TypeSpec 的偏移和散列。

## 刻意保留的边界

当前状态域只支持“已证明为新的空队列”，不支持把未知队列当空、不支持 Recycle/Enqueue、不支持非空 Dequeue。要扩展为通用池生命周期，必须先证明：

1. 精确 Recycle 泛型类型分派、cast 和锁 finally 的正常返回行为；按数组身份执行 enqueue，拒绝未知/外逃引用。
2. 队列的有序内容和 dequeue 后的别名关系，包含重复回收、null、错误长度、跨实例回收以及写入已发布数组的影响。
3. float 的完整 Create/Get 效果，尤其浮点索引 `conv.i4` 的有效范围、非有限值及截断；不能套用 int 索引解释。
4. 非空 custom 仅已闭合精确 integral primitive/Nullable 字面量分支，详见 [custom 字面量证明](SET-FACTORY-CUSTOM-LITERALS.zh-CN.md)。其他 struct/class/enum、ChangeType 和默认值构造仍未闭合；任何未知副作用都必须停止共享状态传播。
5. 整个 Count/Sets 初始化器的副作用闭合、所有数组后续读写和引用逸出，以及最终使用点的状态证明。

完整生产语义、源版本与归档绑定、独立审查及发布门禁未改变。`wholeInitializerProven`、`numericSizeProven`、`normalReturnGuaranteed`、`runtimeSnapshotUsable` 均为 false。现有四组 dispatch 配方仍标记条件性；新的局部证书不会把它们统一升级为运行时数据。

## 验证

公开测试全部使用原创合成 PE，包含直接/池化 getter、连续多个分配、参数数组覆盖、List 的精确类型与签名、跨字段绑定拒绝、未知调用停止、地址逸出拒绝、失败片段不部分提交、取消、时限与累计证据预算。

```sh
PYTHONPATH=src:tests python -m unittest discover -s tests -p 'test_set_factory*.py' -v
```

对已提供的同安装 1.4.5.8 客户端和服务端输入，仅进行只读字节解析并核对已记录 SHA256。两者均证明 24 个连续分配/存储片段、46 个调用发生位置；其中 11 个是新增移除的残余调用，涉及 List 构造、List.Add 和 CreateIntSet 三类关系。残余从 33 组 / 662 次降至 33 组 / 651 次；组数未下降，因为相同目标在后缀仍有未证明发生位置。

两者都在 IL 888 处停止，后续首个未证明调用位于 IL 1251。该段涉及非空 custom 参数构建，未予跳过或假设纯函数。真实数组内容、原始程序集和完整私有证据不提交公开仓库；所有完整性、可发布性和运行时快照标志保持关闭。

后续 custom 字面量扩展已将边界推进到 IL 1843、37 个片段 / 66 个调用，残余为 32 组 / 643 次。详见 [新增证明与剩余义务](SET-FACTORY-CUSTOM-LITERALS.zh-CN.md)。以上 IL 888 和 24 / 46 计数保留为该前缀证明最初版本的验证基线。
