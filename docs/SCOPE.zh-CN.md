# 资源流水线范围与输入边界

这是独立的资源发布流程演示。原有 Tdecoder、viewer-app、viewer-admin、viewer-boot、TerraWasm 等仓库只读；本仓不复制其私有源码，也不包含 Terraria 游戏程序集、贴图或用户存档。

## 已核对的现实边界

- 小程序已有按提交固定的 CDN 地址、资源缓存、资源分包及部分 CDN-only 打包规则。因此问题是统一资源合同、更新入口与消除内嵌重复数据，不是从零增加一个图片 URL。
- 指定的 1.4.5.8 服务端目录含程序集和运行时，不含完整 XNB 贴图。物品、NPC、人物、装备帧等必须有同版本客户端 Content 或已合法提取的原图输入。
- 现有服务器提取器能生成 ID、本地化、物品运行时属性、物块布局/帧标志、地图颜色、图鉴、宝箱及 CDN 数据包；现有资源脚本仍有版本、文件哈希、客户端绘制规则和额外参考资料约束。
- 客户端绘制算法、WASM 可执行文件、业务代码和用户 plr/wld 存档不应当混进公共资源 CDN。
- 目标 CDN 仓库当前只有读取权限。演示默认向本地 bare Git 仓库发布，不会修改既有 CDN。

## 本仓交付原则

1. 输入来源、版本、散列和提取器版本贯穿任务、预览、发布、客户端校验。
2. 服务器数据和客户端图片分开输入；缺资源、未知提取器版本或规则不兼容时明确阻止完整发布，不自动复用旧版本。
3. ZIP 解包有路径、链接、重复名字、体积、文件数和压缩比例限制；上传内容永远不能指定执行命令。
4. 运行程序集的提取必须由管理员安装的可信适配器在独立无网络、只读输入、有资源上限的工作环境中完成。Web 服务本身不加载上传程序集。
5. 公共 CI 只使用本仓生成的合成资源，游戏包与派生真实资产留在用户控制的私有环境。真实资源公开分发需要另外确认权利和发布范围。
6. 内容寻址对象跨页面/版本去重，元数据按资源族独立压缩。变更预览绑定输入和输出摘要，确认后才生成 Git 提交并发布版本指针。
7. 客户端先验证完整 manifest 和对象散列，再原子切换当前版本；缓存支持按需加载、容量上限和失败保留旧版本；管理员主动回滚流程尚未实现。

## 尚不能承诺的内容

仅从服务端包无法生成全部图片；新版本私有 API、地图规则和人物绘制规则变化不能保证无需适配。完整资源覆盖必须由实际页面消费清单和版本适配器测试证明，不能把合成演示成功当作真实游戏版本提取成功。
